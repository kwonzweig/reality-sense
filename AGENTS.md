# Practical Judgement

This repo develops Practical Judgement: an umbrella for capabilities that help
agents make useful decisions in real contexts. Keep repo content in English.

## Concept structure

- Organize behavioral guidance under named concepts within Practical Judgement.
  Each concept has its own heading, a brief explanation, and concise rules below it.
- Preserve established names and meanings. **Resource rationality** is a named
  concept under Practical Judgement, with its rules for allocating effort beneath
  that heading. Keep its identity as the collection grows.
- Ground established names in sources. If a block has no concept title, first
  determine whether it belongs under an existing concept or falls outside scope.
  Otherwise, research the appropriate name. Give a genuinely new concept a clear
  provisional name and identify it as a repo proposal until its status is settled.
- Each block should address a general decision mechanism. Use examples to explain
  and test it; keep the rules useful beyond the example that prompted them.

## Research and authorship

Start with the [Agentic Stack Catalog](https://kwonzweig-agentic-stack-catalog.kzweig.chatgpt.site/)
and inspect relevant original skills and sources. Reuse what fits. Extend the
search when a gap, competing explanation, or better candidate warrants it;
the current shortlist remains open to revision.

Keep rules self-contained and concise. Put substantial evidence and evaluation
records in supporting documents. Use Humanizer as the writing baseline.

This `AGENTS.md` governs work on this repo. Runtime guidance currently lives in
`skills/reality-sense/SKILL.md`. When proposing an instruction change, name its
actual repo and file, and distinguish a proposed location from an existing one.

## Behavioral changes and evidence

Define the user's intended outcome, explain the observed failure with a testable
causal hypothesis, and inspect active instructions and skill selection before
editing the relevant rule. Use Skill Creator and writing-skills for skill changes.
Compare behavior with the previous version on a new case predicted by the
hypothesis and a countercase requiring different behavior. Check both skill
selection and its effect on the user's task.

Preserve user-reported improvements as useful early evidence. Record what improved
and the context, distinguish observation from causal attribution, and use the
signal to guide further work. See the [initial positive observation](docs/observations/2026-11-07.md).
